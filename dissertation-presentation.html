Efficient Scheduling for Batched AI Jobs

Minimising model-switch overhead in serverless LLM inference through grouping, prefetching, and admission control

Jingsheng Wang MSc Dissertation · 2025
1

Why Batch LLM Inference?

  • Enterprises run thousands of offline tasks daily: summarisation, classification, extraction
  • Researchers submit large-scale benchmarks across multiple models — evaluation suites, leaderboard runs, ablation studies
  • Real-time latency is not required — throughput and cost matter most
  • Serverless platforms scale GPUs to zero between jobs, but model loading is expensive — a single switch costs ~90 seconds

Core Research Question: In offline batch LLM inference — where all tasks are submitted before execution begins — how can the scheduler discover shared structure among tasks (model weights, prompt prefixes) and use it to minimise the total completion time (makespan)?

Contributions

Scheduling Techniques

  • Model-grouped scheduling — reduces switches from O(N) to O(K)
  • Aggressive checkpoint prefetch — overlaps SSD→CPU I/O with GPU compute from the start of each group
  • Memory-aware prefetch guard — skips prefetch when CPU pinned memory is full

System Design

  • Greedy worker assignment — assigns models to GPUs considering cache locality
  • Long-short interleaved sorting — minimises per-GPU I/O idle by alternating large and small tasks
  • Three concurrency strategies (sync, chunked, semaphore) with empirical comparison

Concurrency Strategies

Three strategies control how tasks within a model group are dispatched to the Router:

sync

Sequential

One task at a time. Simplest, lowest throughput. Useful as a baseline.

chunked

Fixed Chunks

Submit buffer_limit tasks, wait for all to finish, repeat. Bursty but predictable.

semaphore · default

Sliding Window

Maintain up to buffer_limit in-flight tasks. As one completes, the next fires immediately. Maximises GPU utilisation.

Semaphore keeps the GPU pipeline full without overwhelming the backend — it is the default for all experiments.

Experiment 1: Strategy Comparison

500 tasks, model grouping ON, aggressive prefetch ON. Comparing concurrency strategies:

Strategy Makespan Throughput Avg Latency
sync ~760s 0.66 t/s 0.5s
chunked (10) ~310s 1.61 t/s 3.2s
semaphore (10) ~260s 1.92 t/s 2.8s

Semaphore achieves ~3x throughput over sync by keeping the GPU pipeline saturated. Chunked leaves idle gaps between batches.

Experiment 3: Scaling Across Model Mixes

Testing with different model compositions (500 tasks each, semaphore strategy):

Benefits scale with model diversity. Single-model workloads have no switches to eliminate. The more distinct models, the more dramatic the improvement — up to 63x for the standard 3-model mix.

Limitations & Future Work

Current Limitations

  • Single-GPU evaluation — multi-GPU scheduling not yet tested
  • Offline batch only — no mixed online/offline priority
  • Memory guard uses size estimates, not live telemetry from sllm-store

Future Directions

  • Multi-tenant extension — global task pool merging across users with fairness guarantees
  • Live memory telemetry — query sllm-store for actual pinned memory usage
  • Hybrid scheduling — mix real-time and batch with priority preemption
15

Conclusion

  • Model grouping reduces switches from O(N) to O(K), turning ~16,450s makespan into ~430s — a 38x improvement
  • Aggressive checkpoint prefetch overlaps SSD→CPU I/O with compute from the start of each group, cutting visible switch cost to ~5s
  • Semaphore concurrency keeps the GPU pipeline full, achieving 3x throughput over sequential execution
  • Greedy worker assignment with long-short interleaving minimises per-GPU I/O idle time

Together, these techniques achieve up to 63x speedup over naive FIFO, making serverless batch LLM inference practical by turning model-switch overhead from a dominant cost into a marginal one.
